# jieshuoju-prototype

麦芽原型 · 剧集现网 1:1 复刻（《离婚后》示例项目）

在线预览：https://zliangf.github.io/jieshuoju-prototype/

纯静态 HTML，无构建、无后端。现网链路：

```text
首页 → 剧本大纲 → 资产库 → 分集视频（全集）→ 单集工作台
```

## 文件结构

```text
index.html + js/home.js        影视创作首页（上传 / 粘贴剧本、创作设定、风格库、全自动创作）
outline.html                   剧本大纲（脚本很短，直接写在页面里）
assets.html                    资产库列表 + 资产详情工作台（脚本见下方「资产库脚本」）
episodes.html + js/episodes.js 分集视频全集（一键成片 / 专业分镜 / 导演级分镜）
workspace.html + js/workspace.js 第1集单集工作台（样片 480P / 正片 1080P）
console.html                   旧入口，自动跳转到分集视频
js/data.js                     演示数据 ReplicaData + 公共方法 ReplicaUI（toast、积分）

css/common.css                 所有页面都加载：设计变量、顶栏、按钮、弹窗、通用内容页、底部引导条
css/home.css                   首页
css/asset-library.css          资产库列表
css/asset-detail.css           资产详情（形象库、预览、提示词与生成、音色、参考图、图片编辑）
css/workspace.css              单集工作台
css/episodes.css               分集视频
media/                         角色、五视图、场景、道具图片
tools/check.py                 自检脚本
tools/regress.html             样式回归检查
tools/smoke.html               交互冒烟检查
```

## 页面怎么组成

- 每个页面先加载 `css/common.css`，再加载这一页自己的样式；脚本先加载 `js/data.js`，再加载这一页自己的脚本。
- `js/data.js` 必须先加载。它把演示数据挂在 `window.ReplicaData`（资产库里简写为 `D`），把公共方法挂在 `window.ReplicaUI`。
- 页面脚本是普通 `<script>`，没有模块。顶层 `var` / `function` 都是全局的，页面之间不共享状态。
- 演示状态只存在内存里，刷新就回到 `data.js` 的初始数据。比如资产库的「已生成」状态在 `revealedAssets` / `revealedLooks` 里。
- 界面都是脚本拼好 HTML 字符串，再整块替换 `innerHTML`，比如资产库的 `render()`、`renderLookLibrary()`。所以事件统一挂在外层容器上，按 `data-*` 属性判断点中了哪里，不要给重绘后的子元素单独绑事件。
- 因为是拼字符串，用户输入的文字（名称、描述、文件名）放进 HTML 前要处理：保存时用 `cleanText()` 去掉 `< > " &` 并限制长度，展示时用 `escapeHtml()`。
- 页面脚本报错时，`data.js` 会弹「页面出了点问题，刷新后再试」，5 秒内只弹一次。提示最多同时显示 3 条，相同的提示不会叠加。

## 积分和生成任务

- 所有扣积分的地方都先判断余额，不够就提示「积分不足，本次……需要 N 积分」并停止，不会扣成负数。
- 生成是用 `setTimeout` 模拟的。任务结束前如果形象或资产被删掉，`cancelLookGeneration()` 会取消任务、退回积分，到点后不会再弹「生成完成」。
- 单集工作台同一时间只跑一个片段，生成中再点会提示稍候。
- 删除都要二次确认：资产库单个删除、批量删除，详情页悬停删除、多选删除，共用同一个确认弹窗 `openDangerConfirm()`。

## 角色音色

- 音色绑在角色上（`char.voiceBind`），不是绑在单个形象上。角色至少有一个形象生成完成后（`charVoiceReady()`）才显示音色入口。
- 入口只有三处：列表卡片图片右下角的音符图标（已绑定常驻，未绑定悬停出现）、详情预览图左上角的音色条、结构图主形象图片底部。都通过 `openVoiceDialog()` 打开同一个弹窗。
- 必须先试听才能点「使用此音色」。角色第一次生成完成时自动弹一次音色弹窗；用户跳过（取消、关闭、Esc）后，这个角色不再自动弹。

## 资产库脚本

`assets.html` 按下面的顺序加载，后面的文件可以直接用前面文件里的变量和函数。只有 `assets-boot.js` 会在加载时执行操作（首次渲染、全局 Esc），其他文件只负责定义函数、挂事件。

```text
js/assets-core.js      共享状态（当前 Tab、多选、已生成记录）、图标、积分单价、生成状态判断、音色试听
js/assets-library.js   列表页：卡片渲染 render()、Tab、集数筛选、搜索、多选、全量生成、删除确认
js/assets-dialogs.js   新增角色 / 子形象弹窗、编辑名称描述弹窗
js/assets-detail.js    详情页：打开关闭、平铺形象卡片、预览图上的音色条、多选、删除、切换角色、集数编辑
js/assets-mindmap.js   详情页结构图（思维导图）：布局、拖动画布 / 分支、缩放、折叠、节点上的新增和删除
js/assets-preview.js   右侧预览：当前形象标题、五视图、历史记录、上传 / 反推、音色弹窗、参考图
js/assets-composer.js  提示词输入、AI 改写、模型 / 比例 / 画质、生成形象
js/image-editor.js     图片编辑（裁剪、旋转、缩放）
js/assets-boot.js      Esc 关闭顺序（从最上层弹窗开始）+ 首次渲染
```

## 样式的分层

每个文件内部仍然按“基础 → 现网精修 → 覆盖”从上往下叠加，**写在后面的生效**，页面之间用加载顺序（`common.css` 在前）保证同样的效果。改样式前先在这一页加载的样式文件里搜索这个选择器，改最后生效的那一处。

`common.css` 开头的“基础”部分是最早的一版，里面还混着资产详情和单集工作台的老样式（例如 `.five-view-missing`、`.look-sheet`、`.tcard`）。这些规则被后面的文件覆盖着，单独挪走会改变覆盖顺序，所以暂时留在原处。

## 修改约定

1. 改了 `css/` 或 `js/` 下的文件后，运行 `python3 tools/check.py --bump`，把所有页面的版本号统一换新。否则别人浏览器里还会用旧缓存。
2. 推送前运行 `python3 tools/check.py`，有「错误」要先修。推到 GitHub 后也会自动跑一遍，结果在仓库的 Actions 页面。
3. 只改样式、不想改变其他页面时，先打开 `tools/regress.html` 点「记录基线」，改完点「对比」。只有你想改的地方出现差异，才算没误伤。
4. 改了交互后，打开 `tools/smoke.html` 点「开始检查」。它会依次打开首页、剧本大纲、资产库、资产详情、分集视频、单集工作台，把能点的按钮逐个点一遍，任何一步出现脚本报错都会标红，并写明点的是哪个按钮。全部「通过」再推送。
5. `check.py` 除了版本号和无用文件，还会检查：每个页面的脚本里用 `getElementById` / `querySelector("#…")` 取的元素是否存在；同一页面的几个脚本有没有重名的全局函数或变量（重名时后加载的会悄悄覆盖前面的）。
6. 新增图片放进 `media/` 对应目录。不再使用的图片和样式及时删掉，`check.py` 会列出来。

本地预览：

```bash
python3 -m http.server 8765    # 然后打开 http://127.0.0.1:8765/
```

## 待解决的问题

按优先级从高到低，每处理完一项就从这里删掉。

1. **剩余的重复选择器**：按页面拆分后还剩约 70 个选择器重复出现，主要在 `common.css`（60 个）。它们中间夹着其他会覆盖同一属性的规则，合并会改变效果，需要逐个看页面后手动合并，合并完用 `tools/regress.html` 对比。
2. **首页上传交互**：拖拽区不能点击、拖进来没有反馈；「粘贴文本」实际是切换面板；「或选择上传方式」点了没有菜单；图标只写 TXT，实际支持四种格式；粘贴为空时也会塞入示例文本；上传成功后的卡片太空，删除按钮不明显。
3. **图片体积**：首页和工作台图片已改为滚动到才加载，但单张图仍然偏大（共约 4MB）。以后有原始素材时，按实际显示尺寸重新导出一份更小的图。

## 协作方式

完整流程和可直接复制给 AI 的提示词见 [协作指南.md](./协作指南.md)。简要步骤：

1. 修改前先拉取最新版本（GitHub Desktop 点 `Fetch origin` / `Pull origin`）
2. 修改页面
3. 填写修改说明后 `Commit`，再 `Push origin`
4. 约 1–2 分钟后在线预览自动更新

历史版本可在 `Commits` 中查看与回退；评审通过的版本在 `Releases` 中打标签（如 `v1.0`）。
